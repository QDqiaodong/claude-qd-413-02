# 录音棚管理系统

录音棚（录音室 / 录音设备 / 预约 / 曲目）的台账与预约流转管理。基于 Spring Boot 3.3 + Vue 3 + MySQL + Redis，docker compose 一键启动。

## 启动

```bash
./start.sh
```

启动后访问 http://127.0.0.1:8243/ 。

## 模块

- 录音室：各录音室的设备占用率环形展示，占用中房间禁止修改功率；卡片可切换房间状态（空闲/占用/维护）；顶部展示全棚功率已占合计与上限，可调整上限
- 录音设备：双击名称/类型单元格行内编辑，归属室必须存在；状态下拉可报故障，报故障当场拆占用（见下）
- 预约：待确认→进行中→已完成 步骤条推进，同房间时段重叠拦截，占用中设备不可重复约（带 @Version 乐观锁）；新开预约与推进进行中受故障闸门与功率硬上限拦截（见下）
- 曲目：按预约归属的曲目星级评分，评分 1~5，可清星（置为未打星）
- 母带放行：母带放行台，规则见下

### 设备故障与功率上限规则

- **报故障当场拆占用（棚控口径）**：设备状态改为「故障」时，故障件所在房间只要还有进行中预约，同一事务内把这些预约当场打回待确认、房间改回空闲；拆不干净整笔回滚，设备状态也不落库。房间没有进行中预约时只改设备状态，不动房间。
- **故障闸门**：房间存在故障设备时，禁止在该房间新开进行中场次或把待确认推进进行中；待确认预约可以留着，等设备修好（状态改回）后再推进。
- **功率硬上限（电工口径）**：全棚功率合计上限默认 7000W（可调）。新开预约、把待确认推进进行中，都要先把「占用房 + 有进行中预约的房 + 本次目标房」的功率加总，超限当场拦住、整笔退回，房间和预约停在原状——不是黄条提醒。目标房已在活跃集合则不重复计入；推进已完成等降载方向的操作不查功率。
- **并发与重核**：改设备状态与开预约并发时，按「功率上限行 → 房间行 → 预约行」的固定顺序加悲观锁串行，双方只看对方提交后的占用与设备状态，不会两笔都按旧空闲落库；失败后再点按当下的设备、房间、预约重核，不使用失败前的快照。

### 接口

- `GET /api/settings/power-limit`：查看功率上限与当前已占合计（`{limit, inUse}`）
- `PUT /api/settings/power-limit`：调整功率上限（body：`{"value": 7000}`，必须为大于 0 的整数）

### 母带放行规则

- 放行单必须挂在**已完成**的预约上（进行中/待确认不许开单），开单同时必须勾入该预约下**至少两首已打星**曲目作为齐件；未打星、归属别的预约的曲目勾不进来。
- 单据状态机：**待齐件 → 会签中 → 已放行**，只能逐格向前，不能跳步、不能倒回；已放行不可改齐件/删除。
- 提交会签与重新会签都按**当时的库内状态**实时复核（不使用历史快照）：
  - 预约此刻仍为已完成；
  - 勾入的曲目此刻仍有星级（会签中途掉星即失败）；
  - 预约的录音室此刻不是维护（母带室口径优先：维护中房间柜子上锁、带子拿不出来，即使带子已录完也不放行）。
- 任一条件不符：整单停在「会签中」，写清全部失败原因，齐件不做部分勾改（不出脏单）；解除原因后可重新勾齐件 / 重新会签。

### 接口

- `GET/POST /api/master-releases`：列表 / 开单（body：`bookingId`、`trackIds`）
- `PUT /api/master-releases/{id}/items`：重新勾齐件（待齐件、会签中可改）
- `POST /api/master-releases/{id}/submit-sign`：提交会签（待齐件 → 会签中 → 实时校验）
- `POST /api/master-releases/{id}/retry-sign`：会签中重新会签（实时复核）
- `DELETE /api/master-releases/{id}`：删除未放行单据（连同齐件）
